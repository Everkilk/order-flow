# OrderFlow: updated tester guidance

## Order ID and document number

The **Order ID** is the internal number the website uses to identify an order. The **document number** is the readable reference assigned to the order. They can differ: Order ID 29 may have document number `DEMO-V2-ORD-25`. The Orders list and detail now show both. Follow the document link to see the exact order; do not infer its ID from the digits at the end of its document number.

## Creating a return

Choose a fulfilled order from the searchable **Fulfilled order** selector. Each option displays the document number, Order ID and status. Search by document number or exact Order ID. Selecting **Create a return** on a fulfilled order preselects it. Choose one of that order's permitted warehouses, add only returnable order items, then save and post. A draft, confirmed, cancelled, inaccessible or fully returned order cannot be used to post an additional return.

## Stock-request evidence

While a request is **Pending**, its creator can upload or delete an incorrect evidence file. Select **Delete** next to that file and confirm its name. Other users, including managers who did not create the request, cannot delete it. Once a decision is recorded, upload and delete are locked. The deletion history stays visible to permitted viewers. A removed file disappears from the active list immediately; background storage cleanup may take a short time. If the history says cleanup failed, contact an administrator with the request and filename; do not upload the same image merely to hide the failure.

## Save/retry when the connection fails

The save button locks while a request is running. If the connection fails at an uncertain point, keep the same form values and retry the same submission. After a reload, use **Check previous submission** if the banner appears. If it says completed, review the linked record before creating another. If it remains unconfirmed, return to the form and retry the same values within 24 hours in that browser session. Do not deliberately double-click or change the values during an unconfirmed retry. After the 24-hour recovery window or a cleared browser session, inspect the relevant record list first so you do not unintentionally create a duplicate.
